RustNFS 0.1.2 — Windows x64

Rust 编写的 NFSv3 目录共享工具，包含原生 Windows 界面与命令行后端。
基于开源 NFSv3 协议库构建；不需要激活，运行 EXE 不需要安装 Rust。
目标系统：Windows 10（1607 及以上）/ Windows 11 x64。

0.1.2 更新与升级

“连接设置”中可修改 Portmapper、MOUNT、NFS 端口，范围 1–65535，三项须不同。
“保存设置”可直接保存而不启动服务；“恢复默认端口”仅恢复这三项为
111 / 20048 / 2049，其他配置保留，之后仍需保存设置或启动服务。
若启动报端口占用（10048），可停止原服务，或改用空闲端口；例如依次尝试
11111 / 20049 / 2050，但这些候选端口也可能已被占用。
改端口后重新复制挂载命令，并更新已有防火墙规则。

升级时先停止服务并关闭 GUI，只替换 rustnfs-gui.exe 和 rustnfsd.exe，
保留原来的 rustnfs.json。配置格式不变。
有共享目录访问权的普通账户即可运行；读写共享还需要相应写入权限。
程序不会修改目录 ACL；防火墙规则仍需按下文手动以管理员身份设置。
本版保留 0.1.1 的 NFS3ERR_ACCES 启动修复：原目录接口错误无法靠提权解决。

开始使用

1. 将整个压缩包解压到可写目录。如果旧 NFS / Portmapper 服务仍在运行，
   先停止它，避免占用相同端口。
2. 运行 rustnfs-gui.exe，浏览选择要共享的文件夹，填写 share 等共享名称，
   点击“添加共享”。默认只读；需要上传文件时取消“只读共享”。
3. 把“允许客户端 IP / 网段”改成开发板的实际 IP，例如 192.168.1.50/32。
   多个地址用英文逗号分隔；初始值 127.0.0.1/32 只允许本机。
4. “监听 IPv4”可以保留 0.0.0.0；“本机 IPv4（用于命令）”应填写开发板
   能到达的 Windows 局域网地址，例如 192.168.1.10。
5. 点击“启动服务”，等状态显示正在运行，选中共享，点击“复制 TCP”，
   在开发板上执行复制的命令。命令已包含 NFSv3、nolock 和端口参数。

停止与设置

配置保存到程序旁的 rustnfs.json。运行时先停止服务，再修改配置。
关闭窗口会停止本 GUI 启动的服务。服务重启后，客户端需卸载并重新挂载。
命令行方式：rustnfsd.exe --config rustnfs.json；Ctrl+C 或输入 stop 回车停止。

无法连接时

检查两端 IP、允许列表和端口占用，再检查 Windows 防火墙。
需要创建规则时，在管理员 PowerShell 中，从本目录手动运行：

    .\scripts\allow-firewall.ps1 -WhatIf
    .\scripts\allow-firewall.ps1

规则限定本程序、已配置的客户端、TCP/UDP 三个端口，以及专用网络。
默认端口是 111、20048、2049；首次保存配置后再运行脚本。

本版范围

提供 NFSv3 TCP/UDP、多目录、普通文件读写、只读限制和客户端 IP/CIDR 限制。
不支持 NFSv2/v4、NLM 文件锁、符号/硬链接和特殊文件；不适合作为 Linux rootfs。
UID/GID 为固定映射，mode 变更仅在本次运行期间生效，不是完整的 POSIX 权限系统。

验证情况

0.1.0 历史结果为 Linux 协议 35/35、Windows EXE / Wine 9 协议 35/37。
Wine 9 的目录接口行为与真实 Windows 不同，旧测试漏掉了已在 0.1.1 修复的启动问题。
各版本复测结果及实体 Windows 验证范围见 docs/test-results.md；
这些历史数字不代表 0.1.2 已完成相同验证。
