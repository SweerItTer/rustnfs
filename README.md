# RustNFS 0.1.2

面向 **Windows 10（1607 及以上）/ 11 x64** 的轻量 NFSv3 目录共享工具，使用 Rust 和原生 Windows 界面，并基于开源 NFSv3 协议库构建。适合在可信开发网络中向 Linux 开发板共享普通文件，不需要激活。

## 0.1.2 更新与升级

“连接设置”中可直接修改 **Portmapper、MOUNT、NFS** 三个端口；端口须在 **1–65535** 内且各不相同。点击“保存设置”即可保存配置，无需启动服务。“恢复默认端口”只把这三项改回 **111 / 20048 / 2049**，其他配置保留；之后仍需点击“保存设置”或“启动服务”才会保存。

若启动报端口占用（Windows 错误 **10048**），可停止占用端口的原服务，或换一组空闲端口，例如依次尝试 **11111 / 20049 / 2050**；这些候选值也可能已被占用。改端口后，重新复制界面生成的挂载命令，并更新已有防火墙规则。

**升级时先停止服务、关闭 GUI，只替换 `rustnfs-gui.exe` 和 `rustnfsd.exe`，保留原来的 `rustnfs.json`。** 配置格式不变。程序通常可由有共享目录访问权限的普通账户运行；读写共享还需要相应写入权限，程序不会修改目录 ACL。防火墙规则仍按下节说明手动以管理员身份配置。

本版保留 0.1.1 的启动修复：更换了不支持目录的 `ReOpenFile` 调用，解决由此产生的 `NFS3ERR_ACCES`；这类接口错误无法靠管理员权限解决。

## 开始使用

如果旧 NFS / Portmapper 服务仍在运行，先停止旧服务，避免占用相同端口。

1. 将完整压缩包解压到可写目录，运行 **`rustnfs-gui.exe`**。浏览并选择一个已存在的**绝对目录**，填写共享名，例如 `share`，然后点击“添加共享”。新共享默认**只读**；需要开发板写入时，取消只读后再添加，或选中已有条目并点击“更新选中”。
2. 将“允许客户端 IP / 网段”从初始的本机回环地址，改为开发板的精确 IP，例如 `192.168.1.50/32`。需要整个开发网段时可填 `192.168.1.0/24`；多项用英文逗号分隔。只填写确实需要访问的设备或网段。
3. “监听 IPv4”可保留 `0.0.0.0`，表示监听本机所有 IPv4 网卡。**“本机 IPv4（用于命令）”应填写开发板能到达的 Windows 局域网地址**，例如 `192.168.1.10`；挂载目标不能填写 `0.0.0.0`。
4. 点击“启动服务”，等状态显示运行后，选中共享并复制 **TCP 挂载命令**，在开发板上以具备挂载权限的用户执行。命令已经包含 `vers=3,tcp,mountproto=tcp,nolock` 和实际端口；确需 UDP 时可用界面中的 UDP 命令。

设置保存于程序旁的 `rustnfs.json`。服务运行期间先停止再修改配置。点击“停止服务”或关闭 GUI，会停止该 GUI 启动的服务进程。单独运行 `rustnfsd.exe --config rustnfs.json` 时，可按 **Ctrl+C**，或在标准输入键入 `stop` 后回车停止。**服务重启后，客户端需要卸载旧挂载并重新挂载。**

## Windows 防火墙

如果开发板无法连接，先检查 IP、客户端允许列表、端口占用和网络连通性。需要放行 Windows 防火墙时，在 GUI 保存配置后，由你手动以**管理员身份**打开 PowerShell，在解压目录运行：

```powershell
.\scripts\allow-firewall.ps1 -WhatIf   # 预览
.\scripts\allow-firewall.ps1           # 应用
```

脚本只为本目录的 `rustnfsd.exe` 创建或更新入站规则，限定 `allowed_clients`、**Private（专用）网络**以及配置中的三个固定端口，分别允许 TCP 和 UDP。默认端口为 111、20048、2049。脚本不会切换网络类型或关闭防火墙；连接开发板的网卡需由你确认是可信的专用网络。修改客户端、端口或移动程序目录后重新运行脚本；它不会删除其他规则。

## 支持范围与限制

- 支持 **NFSv3 over TCP / UDP**、多个共享目录及只读 / 读写设置；不支持 NFSv2、NFSv4 或 NLM 文件锁，客户端必须使用 `nolock`。
- 不支持符号链接、硬链接及设备等特殊文件操作，不适合作为 Linux 根文件系统（rootfs）。共享普通项目文件或构建产物前，请先在目标开发板上验证自己的工作流。
- NFS 属性使用配置中固定的 `uid` / `gid`，权限位是运行期间的 mode 投影，并非完整的 POSIX 权限系统，也不会转换为 Windows NTFS ACL。实际磁盘访问受运行程序的 Windows 用户权限限制；运行期 mode 变更不持久化。

## 从源码构建

安装 **Rust stable（至少 1.88）**，以及 MSVC Build Tools 的“使用 C++ 的桌面开发”组件和 Windows SDK（[Rust 官方要求](https://rust-lang.github.io/rustup/installation/windows-msvc.html)）。在源码目录的 Developer PowerShell 中运行：

```powershell
.\scripts\build-windows.ps1
```

脚本执行 `cargo build --locked --release --target x86_64-pc-windows-msvc`。两个 EXE 输出到 `target\x86_64-pc-windows-msvc\release\`，运行时将它们放在同一目录。

0.1.0 的历史测试为 Linux 协议 **35/35 通过**、Windows EXE / Wine 9 **35/37 通过**。Wine 9 当时允许了真实 Windows 会拒绝的目录 `ReOpenFile`，因此这些历史结果漏掉了后来在 0.1.1 修复的启动问题，也不能作为 0.1.2 的验证结论。**各版本实际复测结果见 [测试结果](docs/test-results.md)**；实体 Windows 和目标开发板上的验证范围以该记录为准。
